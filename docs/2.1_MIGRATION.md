# Brain SDK 2.1 Migration Guide

## Who This Guide Is For

This guide is for two audiences:

- Human firmware engineers migrating existing apps to SDK 2.1.
- Agentic/codegen workflows that need deterministic migration rules and validation steps.

The goal is to preserve source compatibility while explaining the runtime behavior changes that matter for audio quality, pot responsiveness, and init flow.

## Executive Summary

SDK 2.1 unifies analog sampling behind a shared DMA-backed `AdcEngine`. `Pots`, `Inputs`, and `AudioProcessor` now consume a shared ADC sample cache instead of each owning separate ADC read strategies.

Practical impact:

- Most existing firmware compiles unchanged.
- Init order between `init_pots()`, `init_inputs()`, and `init_audio_processor()` is now flat (no conflict ordering needed).
- Pot and input reads are non-blocking from the app perspective.
- Several legacy toggles and update calls are now no-op shims kept for compatibility.

## Compatibility Contract

2.1 is designed as a non-breaking release at the public API level.

What remains source-compatible:

- `Brain` wrapper API surface.
- `Pots`, `Inputs`, and `AudioProcessor` public method names.
- Existing `AudioProcessorConfig` fields (including legacy fields).

What changed behaviorally:

- Some legacy methods/fields are accepted but ignored at runtime.
- Sampling freshness no longer depends on explicit `scan()`/`update_audio_cv()` calls.
- Audio input in single-stream mode includes an optional deglitch stage enabled by default.

## Architecture Change (Important)

Before 2.1, multiple components configured ADC/DMA independently, which forced ownership guardrails and awkward init-order workarounds.

In 2.1:

- `AdcEngine` is the sole owner of ADC + DMA ring capture.
- Consumers read per-channel latest values from `AdcEngine`.
- `AudioProcessor` drains ADC ring inline in its audio tick and reads latest channel values.
- `Pots` runs a timed mux state machine and samples from the shared cache.
- `Inputs` reads from the same shared cache.

This removes most cross-component ADC contention by design.

## Human Migration Steps

### 1. Remove old init-order workarounds

If your firmware had defensive sequencing for ADC ownership, simplify it.

```cpp
// Old defensive style
if (!brain.is_pots_initialized()) {
    brain.init_pots(create_default_pots_config(3, 8));
}
brain.init_audio_processor(cfg, cb, ctx);  // used to fail in some orderings

// 2.1 style
brain.init_pots(create_default_pots_config(3, 8));
brain.init_audio_processor(cfg, cb, ctx);  // order-safe with init_inputs/init_pots
```

### 2. Move pot tuning to `PotsConfig`

These `AudioProcessorConfig` fields are legacy-compatible but ignored:

- `enable_pot_mux`
- `pot_count`
- `pot_settle_discard_samples`
- `pot_average_samples`
- `max_dma_drain_samples_per_tick`

Use `PotsConfig` instead:

```cpp
PotsConfig pcfg = create_default_pots_config(3, 8);
pcfg.samples_per_read = 8;
pcfg.settle_us = 2000;
brain.init_pots(pcfg);
```

### 3. Keep or remove legacy update calls (optional)

The following are no-op in 2.1 and can be removed for clarity:

- `brain.update_pots()`
- `pots.scan()`
- `brain.update_inputs()`
- `inputs.update_audio_cv()`

They are still safe to leave in place during staged migration.

### 4. If you instantiate `AudioProcessor` directly, wire pots explicitly

`Brain::init_audio_processor(...)` wires `Pots` automatically when available.

If you bypass `Brain`:

```cpp
Pots pots;
AudioProcessor proc;

pots.init(create_default_pots_config());
proc.set_pots(&pots);  // required for frame->pot_raw_u8[] and get_pot_raw_u8()
proc.init(cfg, my_callback, my_ctx);
```

## Behavior Changes You Should Know

### `Pots` read API behavior

- `pots.get(i)`: latest buffered mapped value.
- `pots.get_single(i)`: compatibility alias for buffered read.
- `pots.get_raw(i)`: latest buffered raw value.
- `pots.scan()`: no-op compatibility shim.

### `Inputs` behavior

- `inputs.update_audio_cv()`: no-op compatibility shim.
- `inputs.set_audio_cv_dma_enabled(...)`: no-op compatibility shim.
- `inputs.is_audio_cv_dma_enabled()`: always `true` in unified mode.

### Brain-level ADC policy toggles

The following remain for source compatibility and have no runtime effect in 2.1:

- `Brain::enable_adc_optimization(bool)`
- `Brain::set_audio_cv_dma_enabled(bool)`
- `Brain::set_shared_pot_sampling_enabled(bool)`

### Audio input deglitching (new default)

`AudioProcessorConfig` now includes:

- `input_deglitch_enabled` (default `true`)

This enables a lightweight median-of-3 filter on single-stream audio input, primarily to suppress isolated impulse clicks from ADC discontinuities. Disable only if you explicitly want absolutely minimal callback-path processing and have confirmed your input path is already clean.

## Legacy No-op Shim Inventory

You can keep these during migration; they compile and run safely.

- `Brain::enable_adc_optimization(bool)`
- `Brain::set_audio_cv_dma_enabled(bool)`
- `Brain::set_shared_pot_sampling_enabled(bool)`
- `Pots::set_simple(bool)`
- `Pots::set_optimized_sampling_enabled(bool)`
- `Pots::is_optimized_sampling_enabled()`
- `Pots::set_settling_delay_us(uint32_t)`
- `Pots::scan()`
- `Inputs::set_audio_cv_dma_enabled(bool)`
- `Inputs::is_audio_cv_dma_enabled()`
- `Inputs::update_audio_cv()`

## Agentic Migration Checklist

Use this when updating many firmware apps automatically.

### A. Search and classify

1. Find all audio init call sites:
   - `init_audio_processor(`
2. Find legacy pot/audio config usage:
   - `pot_average_samples`
   - `pot_settle_discard_samples`
   - `enable_pot_mux`
   - `pot_count`
3. Find legacy polling no-ops:
   - `update_pots(`, `pots.scan(`, `update_inputs(`, `update_audio_cv(`

### B. Transform safely

1. Remove init-order guard code that exists only for old ADC ownership conflicts.
2. Move effective pot tuning into `PotsConfig`.
3. Keep no-op calls initially unless style cleanup is explicitly requested.
4. If raw `AudioProcessor` is used, ensure `set_pots(&pots)` exists when pot frame data is required.

### C. Validate

1. Build firmware targets.
2. Run manual hardware sanity:
   - Audio passthrough stable at configured sample rate.
   - Pot value changes reflected in callback/frame or `pots.get()`.
   - No periodic hard stalls in audio tick counter.
3. Confirm no regression in docs/examples for updated apps.

## Troubleshooting During Migration

### Symptom: no sound after adding pot-controlled gain

Likely cause: gain source defaults to `0` before pot data is updated.

Fix pattern:

- Initialize gain state to unity (`255` in Q8 scale).
- In audio callback, prefer `frame->pot_raw_u8[0]` when available.
- Keep a fallback to previous gain value.

### Symptom: random quiet pops on otherwise clean source

Likely cause: isolated ADC sample impulses.

Fix pattern:

- Keep `AudioProcessorConfig::input_deglitch_enabled = true` (default).
- If disabled for benchmarking, re-enable and compare.

### Symptom: audio runs briefly then hard-freezes

Signal: diagnostic tick/sample counters stop increasing.

Action:

- Update to latest 2.1 branch state where scheduler stability fixes are included.
- Confirm timer/tick counters continue increasing in runtime logs.

## Suggested Verification Matrix

After migration, test at least:

1. `AudioProcessorTest`
2. `AudioVolumeTest`
3. `PotReadStabilityTest`
4. Any app combining pots + audio + CV outputs

For each, verify:

- Initialization succeeds regardless of init order among `pots/inputs/audio`.
- Audio callback remains stable over extended runtime.
- Pot motion is reflected without blocking artifacts.

## Migration Impact Statement Template

Use this in PR descriptions:

1. This change keeps public SDK APIs source-compatible with 2.0 usage.
2. Legacy ADC/pot tuning toggles remain accepted as no-op shims.
3. Runtime behavior now uses unified DMA-backed ADC sampling via `AdcEngine`.
4. Pot/input/audio coexistence no longer depends on strict init order.
5. Hardware verification was run on target board with sustained audio + pot activity.
