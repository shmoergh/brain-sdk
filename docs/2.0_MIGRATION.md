# Brain SDK Migration Guide (`main` -> `2.0-oo`)

This document maps the old API on `main` to the refactored class-based API on `2.0-oo`.

Scope:
- Old baseline: `lib/brain-common`, `lib/brain-io`, `lib/brain-ui`, `lib/brain-storage`, `lib/brain-utils`
- New baseline: `brain/brain.h`, `brain/include/*`, `brain/src/*`

## Breaking Changes At a Glance

1. Include paths changed from `lib/.../include/...` to `brain/...`.
2. Most public namespaces were removed from core SDK usage.
3. `Pulse` was split into `Inputs` (input side) and `Outputs` (output side).
4. `AudioCvOut` voltage API changed from float volts to integer millivolts.
5. Output coupling API (`AC/DC`) was replaced by explicit output range API.
6. `AudioCvIn` voltage getters changed from float volts to integer millivolts.
7. `Led` and `ButtonLed` were folded into `Leds`.
8. Monorepo structure changed from multi-library `lib/*` to one `brain` module.
9. `Brain` `init_*` APIs now return `BrainInitStatus` (`kOk`, `kAlreadyInitialized`, `kFailed`).
10. `MidiToCV` now uses dependency injection (`set_dependencies`) instead of owning internal `Outputs`/`MidiParser`.
11. `BrainT` and preset aliases were removed; feature selection now uses explicit `BRAIN_USE_*` macros.

### Coupling/Range Mapping

| Old | New |
|---|---|
| `AudioCvOutCoupling::kDcCoupled` | `AudioCvOutRange::kRange0To10V` |
| `AudioCvOutCoupling::kAcCoupled` | `AudioCvOutRange::kRangeMinus5To5V` |

Notes:
- New API is explicit about expected user input range.
- In `kRange0To10V`, `set_voltage_millivolts` expects `0..10000`.
- In `kRangeMinus5To5V`, it expects `-5000..5000`.

### Storage

Storage function names are unchanged; namespace moved:
- `read_cv_calibration(...)` -> `read_cv_calibration(...)`
- `write_cv_calibration(...)` -> `write_cv_calibration(...)`
- and similarly for region/app blob helpers.

Calibration data format remains `CvCalibrationV1` with the same layout, so existing saved calibration data is preserved.

### MidiToCV Utility

| Old | New | Status |
|---|---|---|
| `bool init(AudioCvOutChannel, uint8_t)` | `BrainInitStatus init(AudioCvOutChannel, uint8_t)` | Breaking return type |
| (internal ownership of `Outputs`/`MidiParser`) | `set_dependencies(Outputs*, MidiParser*)` before `init(...)` | Breaking ownership model |
| direct utility init with no Brain orchestration | `Brain::init_midi_to_cv(...)` preferred | New wrapper path |

Notes:
- `Brain::init_midi_to_cv(...)` keeps utility init explicit, but auto-initializes `outputs` and `midi_parser`.
- Init is idempotent and returns explicit status.

## New High-Level Wrapper (`Brain`)

New wrapper in `brain/brain.h`:
- Single public wrapper: `Brain`
- Compile-time feature selection uses explicit macros before include:
  - `BRAIN_USE_ALL`
  - `BRAIN_USE_LEDS`, `BRAIN_USE_BUTTONS`, `BRAIN_USE_OUTPUTS`, `BRAIN_USE_INPUTS`, `BRAIN_USE_POTS`
  - `BRAIN_USE_MIDI_PARSER`, `BRAIN_USE_MIDI_TO_CV`, `BRAIN_USE_POT_MULTI_FUNCTION`
- `BRAIN_USE_MIDI_TO_CV` requires `BRAIN_USE_OUTPUTS` and `BRAIN_USE_MIDI_PARSER`
- `BRAIN_USE_POT_MULTI_FUNCTION` requires `BRAIN_USE_POTS`
- At least one `BRAIN_USE_*` macro must be provided (no implicit default)

Common migration pattern:
- Replace manual init ordering with `brain.init_all()` or selective `init_*()`.
- Call `brain.update_all()` or selective `update_*()` in your loop.
- Check explicit init status:
  - `BrainInitStatus::kOk`
  - `BrainInitStatus::kAlreadyInitialized`
  - `BrainInitStatus::kFailed`

## Migration Examples

### 1) Output voltage + coupling migration

Old:
```cpp
AudioCvOut out;
out.init();
out.set_coupling(AudioCvOutChannel::kChannelA, AudioCvOutCoupling::kAcCoupled);
out.set_voltage(AudioCvOutChannel::kChannelA, 1.25f);
```

New:
```cpp
Outputs out;
out.init();
out.set_output_range(AudioCvOutChannel::kChannelA, AudioCvOutRange::kRangeMinus5To5V);
out.set_voltage_millivolts(AudioCvOutChannel::kChannelA, 1250);
```

### 2) Input voltage migration (float volts -> millivolts)

Old:
```cpp
AudioCvIn in;
in.init();
in.update();
float v = in.get_voltage_channel_a();
```

New:
```cpp
Inputs in;
in.init();
in.update();
int32_t mv = in.get_voltage_millivolts_channel_a();
```

### 3) Pulse class split

Old:
```cpp
Pulse pulse;
pulse.begin();
pulse.set(true);
bool gate = pulse.read();
```

New:
```cpp
Inputs inputs;
Outputs outputs;
inputs.init_pulse();
outputs.init_pulse();
outputs.pulse_set(true);
bool gate = inputs.pulse_read();
```

### 4) Wrapper-based startup

```cpp
#define BRAIN_USE_ALL 1
#include "brain/brain.h"

Brain brain;

int main() {
	brain.init_all();
	while (true) {
		brain.update_all();
	}
}
```

## Suggested Migration Order

1. Update include paths.
2. Remove `brain::io`, `brain::ui`, `brain::storage` namespace qualifiers.
3. Migrate `Pulse` usage to `Inputs` + `Outputs`.
4. Migrate output voltage calls to millivolts and map coupling to range.
5. Migrate input voltage reads to millivolts.
6. Replace `Led`/`ButtonLed` usages with `Leds`.
7. Optionally adopt `Brain` wrapper for initialization/update orchestration.

## Known Compatibility Notes

1. Existing storage calibration data remains compatible (`CvCalibrationV1` unchanged).
2. `AudioCvIn` and `AudioCvOut` class names still exist as aliases, but code should migrate to `Inputs`/`Outputs`.
3. The API is intentionally breaking at source level; no legacy namespace forwarding layer is provided in this branch.
